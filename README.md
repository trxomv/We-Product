# WE Offers — باقات WE المخصصة

موقع عربي RTL متجاوب لعروض WE. الواجهة Vanilla HTML/CSS/JavaScript وتُنشر كملفات static؛ Google Sheets هو مصدر الحقيقة للباقات والأسعار والخصومات والإعدادات والإعلانات وطرق الدفع والإضافات. لا توجد قائمة باقات أو أسعار احتياطية hardcoded في الواجهة.

## مصدر البيانات والتكامل

- **Google Sheet المستخدم:** [ملف الباقات والإعدادات](https://docs.google.com/spreadsheets/d/1njuAIxAfHpQXqNazapKEca-NQ_Czd-yj5GzRSpguVuA/edit?usp=sharing).
- **إعداد عنوان Apps Script Web App:** يوجد عنوان `/exec` الحالي مرة واحدة فقط في `public/site-config.js`. لا تكرر العنوان في ملفات أخرى؛ عند نشر Web App جديد عدّل `sheetsEndpoint` هناك وحده.
- **مصدر كود الجسر:** `apps-script/Code.gs`، وبيان الصلاحيات `apps-script/appsscript.json`.
- الجسر للقراءة فقط، ولا يعرض إلا أوراق الموقع المسموح بها: `Rate Plans-Website` و`Rate Plans_OFFER-Website` و`Rate Plans to 15-Website` و`Rate Plans to EOM-Website` و`Website Settings` و`Announcements` و`Payment Methods` و`Add-on`.
- يقرأ الجسر أوراق الويب المسموح بها فقط: أوراق الباقات والعروض، `Website Settings` (`Settings | Value | Enable`)، و`Announcements` (`No. | Value | Enable`)، و`Payment Methods` (`Payment Method | Enable`)، و`Add-on`. تظهر الإعلانات غير الفارغة والمفعّلة مرتبة حسب `No.`. لا يحتاج `Payment Methods` إلى عمود شعار؛ الشعار يُبحث عنه في الملفات المحلية وفق اسم الطريقة. لا تُضمّن أوراق الأرباح أو بيانات المشتركين.

### إعداد Apps Script أو إعادة نشره

إذا لزم إنشاء الجسر من جديد، انقل `Code.gs` و`appsscript.json` إلى مشروع Google Apps Script المرتبط بالمصنف الصحيح، وراجع صلاحية Sheets للقراءة فقط، ثم انشره كـWeb App مع **Execute as: Me** و**Who has access: Anyone** كي يتمكن زوار الموقع من القراءة. بعد تعديل `Code.gs` احفظ ثم أعد النشر عبر **Deploy → Manage deployments → Edit → New version → Deploy**. حدّث عنوان `/exec` في `public/site-config.js` فقط إذا أنشأت نشرًا جديدًا بعنوان مختلف، ثم أعد الاختبار والبناء. هذا العنوان عام؛ لا تضع أسرارًا أو بيانات حساسة في أوراق الموقع المسموح بقراءتها.

## الواجهة والسلوك

- فئات الباقات تُعرض وفق قواعد التاريخ بتوقيت `Africa/Cairo`. شريط الفئة الرأسي وأيقونتها يظهران فقط في «كل الباقات»؛ وعند فتح فئة محددة يختفي عنصر الشريط ومساحته بالكامل.
- ارتفاع البطاقات طبيعي بحسب العناصر الموجودة. لا تُحجز مساحة للخصم أو السعر القديم عند غيابهما. شارات Sheet هي Pills قابلة للالتفاف، ولا يظهر نص «لكل الشبكات» داخل البطاقة. كل الأرقام المعروضة بالأرقام الغربية `0–9`.
- صفوف Add-ons مبنية من بيانات الشيت وبها أيقونة SVG حسب النوع، ثم معلومات الإضافة والكمية، ثم السعر فقط؛ لا توجد Checkbox أو واجهة اختيار. Minutes تستخدم أيقونة اتصال، وGB أيقونة بيانات، مع أيقونة عامة لأي نوع مستقبلي. لا تؤثر صفوف الإضافات في رسالة واتساب الخاصة بالباقة.
- تحافظ جميع بطاقات الباقات على الخلفية البنفسجية الداكنة نفسها، مع accent نيون مشبع يختلف حسب سعة البيانات كما في المرجع (بنفسجي، وردي، أزرق، أخضر، برتقالي، سماوي، وأصفر ذهبي). يظهر التغيير في الإطار والوهج والرقم وشريط السعر، وليس في لون خلفية الكارت؛ لا توجد خلفيات فاتحة/Pastel أو ألوان مرتبطة بفئة العرض.
- شريط المزايا بالترتيب: «الدفع بعد التفعيل»، «1 ميجا = 1 ميجا»، «1 دقيقة = 1 دقيقة لكل الشبكات»، «بعد انتهاء الجيجات: 1 دقيقة = 1 ميجا»، ولكل منها أيقونة مناسبة.
- التطبيق يحتفظ بآخر بيانات سليمة عند فشل الاتصال ولا يستبدل الأسعار بقيم تجريبية. ملفات صور الموقع وشعارات الدفع والأيقونات محلية.

## التطوير والتحقق

يتطلب Node.js حديثًا ولا يعتمد على حزم تشغيل خارجية:

```bash
npm ci
npm test
npm run dev
```

يفتح خادم التطوير على `http://localhost:3000`. لإنشاء وتشغيل ملفات النشر:

```bash
npm run build
npm run preview
```

ينسخ البناء مجلد `public/` كاملًا إلى `dist/` ويتحقق من عنوان Apps Script ومن ملفات CSS/JavaScript والصور والأيقونات المطلوبة. شغّل `npm test` و`npm run build` بعد تعديل المصدر. تتضمن الاختبارات تطبيع البيانات والخصم ورسائل واتساب، وحل مسارات شعارات الدفع المعروفة والمخصصة، وتصنيف الإضافات وبنية الصفوف بلا اختيار، وترتيب المزايا ومسارات الأصول.

## الاستضافة الثابتة

ارفع **محتويات مجلد `dist/`** كما هي إلى جذر موقع Netlify أو Vercel أو أي استضافة static، أو اربط المستودع بحيث ينفذ `npm run build` وينشر `dist/`. يضبط `netlify.toml` و`vercel.json` هذا المسار للمضيفين المعنيين. لا يحتاج تشغيل الموقع إلى خادم دائم أو قاعدة بيانات. يحتوي ملف ZIP للمشروع على المصدر ونسخة `dist/` المبنية؛ بعد أي تغيير للمصدر أعد البناء ثم ارفع الناتج الجديد.

## المهام المعلّقة والمشكلات المعروفة

- لم يُربط المشروع بحساب Netlify أو Vercel خارجي ولم يُوجَّه إلى نطاق خارجي؛ الرفع إلى حساب المالك خطوة اختيارية.
- يجب أن يظل Apps Script منشورًا ومتاحًا للقراءة العامة، وألا تتضمن أوراق الموقع المسموح بها معلومات سرية.
- صفوف الإضافات معلوماتية فقط؛ لا يوجد اختيار للإضافات ولا آلية دفع/خصم لسعر الإضافة داخل الموقع.
- لوجو طريقة الدفع الجديدة لا يتحدد بمجرد تفعيل `Enable` في Sheet؛ الخلية لا تحتوي مسار صورة. أضف الصورة إلى `public/assets/payment-methods/` باسم صغير/ lowercase يطابق اسم الطريقة بعد تحويل المسافات والـunderscore إلى hyphen، مثل `Payment_Custom_Wallet` ← `custom-wallet.webp`. يدعم الموقع `.webp` و`.png` و`.svg` و`.jpg` و`.jpeg`، ويبحث كذلك في الأسماء المعروفة في `PAYMENT_ASSETS` أولًا. بعد إضافة الملف شغّل `npm run build` وأعد نشر محتويات `dist/`. إذا لم يجد ملفًا صالحًا يظهر اسم الطريقة وبشارة حروف بدل صورة مكسورة؛ وللاسم غير القياسي أضف مساره الصريح إلى `PAYMENT_ASSETS` في `public/js/app.js`.

## حالة المشروع

قُرئت بيانات الباقات والإضافات والإعدادات من المصنف المحدد أعلاه، ولم يجر تعديل Google Sheet. يحتفظ هذا المشروع ببيئة مستقلة ثابتة قابلة للنشر؛ لا ترفع أسرارًا أو ملفات `.env` إلى مستودع عام.
